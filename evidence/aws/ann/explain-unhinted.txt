EXPLAIN — the SAME statement without @ce_ann  (the control)
========================================================================================

The unflattering half, captured on purpose.

ADR 0002 GT-06 recorded that at ~5,200 rows CockroachDB's optimizer does NOT choose the
vector index for this shape — the plan becomes top-k over a scan — and GT-06b recorded
that naming the index makes it traverse. That pair is the stated reason every ANN arm in
MAINLINE pins the index. This file is the control that checks it, against the same rows
and the same bound values as explain-hinted.txt, taken seconds apart.

MEASURED HERE, AND IT IS NOT WHAT THE ADR SAYS: **the unhinted plan also traverses
ce_ann.** On this cluster, today, at this corpus size, the optimizer chooses the vector
index on its own. GT-06 did not reproduce.

That is a single observation, so it was swept: row counts 0, 200, 1100, 5300 in a scratch
database built from the same DDL, with seeded pseudo-random vectors, by
`scripts/aws/ann_proof.py --crossover`. Appendix A is that sweep. It crosses 5,200 —
GT-06's own row count — and the optimizer still picks the index.

APPENDIX B IS THE COUNTERFACTUAL THAT STILL WORKS. Removing the *hint* changes nothing
on this release; removing a *prefix constraint* is refused outright, SQLSTATE 42809,
`index "ce_ann" cannot be used for this query`. That is the rule this design depends
on, and it is enforced by the server rather than by a comment in a migration.

WHAT THIS DOES AND DOES NOT CHANGE.

  * It does NOT weaken the hint. A cost-based choice that has already changed once
    between two measurements on the same cluster is precisely the kind of
    non-determinism that must not sit beneath a safety gate. ADR 0002's DECISION —
    pin the index in every arm — is if anything better supported by this than by the
    finding it was written from.
  * It DOES make ADR 0002's GT-06 row stale for this shape, and
    evidence/aws/ann/ann-proof.json says so under plans.crossover_census. Correcting
    that document is not this worker's file to edit; the measurement is published here
    so that whoever owns it cannot miss it.
  * It does NOT make explain-hinted.txt weaker evidence. The hinted plan still shows the
    C-SPANN tree being descended with both prefix columns bound. What this file removes
    is the ability to claim the hint was *necessary* at this scale, and that claim is
    now absent from every artefact this worker writes.

UNCONTROLLED DIFFERENCES between this sweep and GT-06's original: GT-06's exact prefix
cardinality, vector distribution, statistics freshness and cluster build are not
recorded in ADR 0002, so this sweep matches its row count and its DDL and nothing else.
The honest statement is `did not reproduce under these conditions`, not `was wrong`.

APPENDIX B — THE COUNTERFACTUAL THAT DOES NOT DEPEND ON THE OPTIMIZER
----------------------------------------------------------------------------------------

Removing the hint is one counterfactual. Removing a PREFIX CONSTRAINT is the other,
and it is the one that does not depend on table statistics. Each statement below keeps
`@ce_ann` and changes exactly one thing.

====================================================================================
prefix_dropped_site_id
====================================================================================

SELECT clause_uuid, commit_id, embedding <=> %(vec)s AS dist
  FROM mainline.clause_embedding@ce_ann
 WHERE activity_root = %(root)s
 ORDER BY embedding <=> %(vec)s LIMIT %(k)s

  REFUSED BY THE SERVER — SQLSTATE 42809
  index "ce_ann" cannot be used for this query

  Not a worse plan. A refused one. This is the prefix rule enforced by
  CockroachDB rather than asserted by a comment.
