# The answer key — gold set GS0 and the authored causality behind it

## Read this first

**A synthetic gold set bounds a linker from above. It does not measure real-world precision.**

Every causal fact in this directory was *authored* by the generator that produced the corpus.
The corpus was then written to be consistent with those facts — sometimes completely, sometimes
partially, and sometimes not at all. A linker evaluated against GS0 is therefore being scored on
a world whose causal structure was designed by the same people who designed the linker. That
makes GS0 excellent for three things and useless for a fourth:

| Good for | Because |
|---|---|
| **Catching regressions** | the ground truth never moves, so a drop is a change in the linker |
| **Comparing configurations** | the same bias applies to both arms, so the *difference* is real |
| **Proving the plumbing works end to end** | the mechanism join key, the four bases, the state machine and the refusal are all exercised over rows a loader will accept |
| ~~Estimating precision on a customer's archive~~ | **no.** A number computed here is an upper bound and must be reported as one |

The real-corpus gold sets — MSHA, CSB and regulator alert data, harness-only, never in the demo
tenant — are what settle the question. They live in `tests/fixtures/recall/goldsets/` and are a
different lane's work. `DEMO-HONESTY.md` states this on camera terms; this file states it for
whoever is about to compute a number.

Three further limits, stated because they are the ones a reviewer would otherwise have to
discover:

1. **The negative-control set is adversarial but finite.** Each negative control is paired with
   the *nearest plausible distractor* — preferentially an event that failed the very control
   class the clause asserts, inside the attribution window. That is the hardest pair the corpus
   contains, not the hardest pair that exists.
2. **`p_doc_trace` is a design parameter, not a measurement.** Roughly 55 % of causal facts here
   leave a documentary trace because decision D7 says so. In a real archive that fraction is
   unknown, varies by operator and by decade, and is exactly what capture–recapture is for.
3. **Nothing here says what a human would have judged.** The human-ceiling study
   (incident-ingestion.md §9 method 5) is a study of people, and no generator can stand in for
   it. If two SMEs agree at α ≈ 0.6, no model can be held to 0.9 — and that number cannot be
   read off this directory.

## What is in here

Generated by `python -m mainline_corpus.blame --out <this directory>`. Every file is
byte-reproducible: two runs of the generator produce identical bytes, and
`python -m mainline_corpus.blame.verify` checks that plus eighteen other properties.

### The gold set

| File | What it is |
|---|---|
| `gs0.jsonl` | one judged `(event, clause)` pair per row |
| `gs0.schema.json` | the JSON Schema every row validates against (draft 2020-12) |

Three labels, and a row is exactly one of them:

- **`true`** — the corpus authored this causal fact. `basis` is the strongest edge the archive
  supports, `state` is what that basis is allowed to be, `channel_a_visible` says whether a
  citation resolver can see it, `p_doc_trace` is the probability the trace draw used.
- **`decoy`** — an event sharing the asset, the date window and the era vocabulary of a true
  precursor, differing in hazard energy and in failed control class. `decoy_of` names the true
  precursor it shadows. A linker that returns it is matching words.
- **`negative_control`** — a clause revision with a documented non-incident cause
  (`documented_cause` ∈ scheduled review · template migration · regulatory update · typo fix),
  paired with the event a linker is most likely to attribute it to. **The false-attribution rate
  over this set is the number to publish first.**

`generative_reason` is prose and is mandatory on every row, including the negatives. A row that
cannot say why it is judged the way it is cannot be audited, and an unauditable gold set is an
assertion with extra steps.

### The causality, and the world it acts on

| File | Table | What it is |
|---|---|---|
| `blame_edge.jsonl` | `mainline.blame_edge` | the authored causal facts, in loadable shape |
| `blame_edge_registry.jsonl` | — | per edge: the trace draw, the channel label, the generative reason, the quote reference |
| `clause.jsonl` | `mainline.clause` | every obligation |
| `clause_registry.jsonl` | — | per clause: natural key, control class, setpoint, birth |
| `clause_revision.jsonl` | — | one row per revision that touched a clause: ordinal, printed label, control delta, setpoint on both sides |
| `proposed_revision.jsonl` | — | clause changes that live on a branch and **never merged** |
| `pending.jsonl` | — | every column deliberately left null, and the worker who closes it |
| `pending_reasons.json` | — | the prose behind `pending.jsonl`'s `reason_code`, written once |
| `spine.json` | — | the film's clause: ids, labels and dates, no prose |
| `index.json` | — | the manifest: counts, digests, histograms, the ratios |

`pending.jsonl` carries a `reason_code` rather than the paragraph: five thousand rows and six
distinct reasons would otherwise be two megabytes of duplicated prose in a committed fixture, and
one string in one place is the better discipline anyway.

### The eight realism injectors

| File | Injector | Rate | Proves |
|---|---|---|---|
| `injector_retypeset.jsonl` | full retypeset | 1 per document, 2016-11-21 | clause identity survives a complete reflow |
| `injector_document_split.jsonl` | split / migration | 8 documents, 2019 | blame crosses document boundaries |
| `injector_orphan.jsonl` | orphan clauses | 12 | *"MAINLINE believes an event wrote this — say yes or no under signature"* |
| `injector_weakening_chain.jsonl` | slow weakening | 4 chains × 3 MOCs ≈ 6 years | fixity patrol and bisect |
| `injector_author_churn.json` | author churn | 30 %, measured from stage 1 | why you cannot simply ask someone |
| `injector_decoy.jsonl` | decoy events | 60 | mechanism matching, not vocabulary matching |
| `injector_fleet_sibling.jsonl` | fleet siblings | 9 groups × 3 sites | cherry-pick, and dedup-to-one-check |
| `injector_vocabulary_drift.jsonl`, `injector_drift_pair.jsonl` | vocabulary drift | continuous, 2004 → 2026 | why lexical-only fails |

Two of those are **selections, not injections**. `mainline.event` is stage 1's table and has
exactly one writer; a second generator appending rows to it would silently invalidate the
severity histogram, the Poisson intensity and the self-excitation term. So the decoy set and the
fleet-sibling set are *found* in the timeline the sampler already produced, against a predicate
recorded on every row. A decoy the corpus already contained is a better decoy than one written
to be found.

## How the four bases arise

Two independent draws produce every edge, and keeping them independent is the whole design.

**Draw one — did this event generate this edit?** A revision is a candidate only if the event
failed a control of the class the clause asserts. That is a set operation over
`control_failure.control_class`, never a similarity over text.

**Draw two — did the causal fact leave a documentary trace?** Roughly 55 % do. The basis falls
out of that draw and the state falls out of the basis:

| basis | arises when | state |
|---|---|---|
| `asserted_document` | the record states it — a revision-history line, a CAPA action, an MOC citing the event, a regulator's notice | `active` |
| `asserted_human` | no trace, but an SME confirmed it under signature during adjudication | `active` |
| `derived_documentary` | no trace; two independent documentary facts co-locate it (the edit landed inside the window and its delta touches the control that failed) | `provisional` |
| `inferred_semantic` | no trace and no co-location: nothing but the mechanism and the words | `provisional`, **never active** |

`CHECK inference_never_blocks` is shipped DDL. Nothing in this directory can carry an
`inferred_semantic` edge in the `active` state, and the verifier re-derives that from the emitted
rows rather than trusting the generator that wrote them.

### What the six evaluation methods get from this directory

1. **Held-out asserted links** — mask the `asserted_document` rows (`channel_a_visible: true`)
   and measure recovery. They are real masked positives because the trace was drawn, not assumed.
2. **Negative controls** — the `negative_control` rows. Publish the false-attribution rate first.
3. **Decoy events** — the `decoy` rows, with the differing hazard energy and disjoint control
   classes recorded per row so the failure mode is nameable, not just countable.
4. **Capture–recapture** — channel A is the citation resolver and sees exactly the
   `channel_a_visible` rows; channel B is the semantic linker and is measured at evaluation time.
   Chapman's `N̂ = (n₁+1)(n₂+1)/(m+1) − 1` estimates the residue. **State the assumption out
   loud**: the channels are not fully independent, positive dependence biases `N̂` downward, so
   any coverage claim built on it is optimistic and must be reported that way.
5. **Human ceiling** — not derivable here. See the limits above.
6. **Stability under re-run** — the corpus is fixed, so a flip is the model.

## What is deliberately null, and why that is a refusal rather than a hole

`pending.jsonl` names every one of these, per row, with its owner:

| Column | Owner | Why not filled here |
|---|---|---|
| `blame_edge.commit_id`, `clause.birth_commit` | the worker that mints the commit DAG | a commit id is sha256 over the JCS envelope and cannot be chosen |
| `blame_edge.p_link` | recall lane calibration | it is an isotonic fit on an adjudicated set. The **features** are emitted in full; supplying a plausible probability would launder a calibration one hop upstream — the same defect class as writing a projected column |
| `blame_edge.evidence_quote_sha256` | `corpus-render-cache` | it is the digest of an exact, unique substring of a document that has not been rendered. Every asserted edge carries a `quote_ref` naming which sentence to bind instead |
| `blame_edge.review_sig` | custody lane | a signature is the only column proving a human was in the loop; a fixture signature would make it unfalsifiable |
| `clause_version.canon_text` (and the text columns that follow from it) | `corpus-render-cache` | history first, text second |

**A loader will be refused until those are bound, and it is right to refuse.** That is the same
posture stage 1 takes on `change_request.merged_commit`.

Two further deliberate absences:

- **No projected column appears anywhere.** `sev_max`, `blood_root`, `blood_peaks`,
  `blood_size`, `virulence`, `ancestor_events`, `max_severity` and the rest are written by
  triggers from the blame ancestry. The emitter refuses a row that names one, and the verifier
  re-derives the denylist rather than trusting the emitter (decision D8, principle P2).
- **`delta_basis` is never `'lattice+model'` and no row carries a `model_id`.** That value means
  a model resolved an inconclusive lattice verdict, and `model_named_when_model_used` would then
  require the model's name. **No model ran in this stage.** Writing one down would put a false
  provenance claim in the one column whose job is to record whether a machine or a person
  decided.

## Identity: recompute, never look up

Every id is `uuid5(CORPUS_NS, "<entity>:<natural key>")` where
`CORPUS_NS = uuid5(NAMESPACE_DNS, "mainline.corpus.0xMAINLINE")`.

```
clause_uuid   = sid("clause", "MRD/PRO-MEC-014/7.3")
event_id      = sid("event",  "INC-2013-044")
site_id       = sid("site",   "MRD")
doc_id        = sid("doc",    "MRD/PRO-MEC-014")
```

A `clause_key` names **where the obligation was born**, not where it lives. The film's clause is
`MRD/PRO-MEC-014/7.3` in 2026 too, three documents and two numbering schemes later. That is the
Akoma Ntoso `@wId` discipline: `printed_label` and `ordinal` are presentation and live on the
version; the uuid is identity and is minted once.

There is no registry to keep in sync. Any worker can compute any id from a natural key printed in
`anchors.yaml` without reading a byte of this directory.

## Regenerating and verifying

```bash
python -m mainline_corpus.blame --out verticals/mainline/fixtures/corpus/answer-key
python -m mainline_corpus.blame.verify --repo-root .
```

The generator rebuilds stage 1 in memory rather than reading it off disk — it is pure and takes
under two seconds, and a stage that depended on another worker's output *directory* could not
prove its own reproducibility without first proving theirs. Pass `--skeleton <dir>` to
**cross-check** the rebuilt world against a stage-1 tree; a mismatch is a refusal naming the
first difference.

`verify` generates the tree twice into throwaway directories and then reads the bytes back off
disk. That distinction matters: the generator already re-checks basis-graded force over its own
objects, but a serialisation bug, a sort-key collision or a float that does not round-trip is
invisible from there and fatal downstream.

Neither command opens a socket, reads a clock, or calls a model.
