# DEMO-HONESTY — what is real, what is synthetic, what was staged, and what does not exist

**This document carries no numbers.** Every count, version, region, digest and census on the
four-column card is read by `honesty/gen_card.py` from `corpus.lock.json` and the **G1
ground-truth attestation**, and is rendered into `honesty/card.html`. A number typed by hand
here would be a number that drifts one corpus regeneration later, and a *drifted honesty card*
is worse than no honesty card: it is a document whose only value is its accuracy, being
inaccurate, on camera, in front of the people you were trying to be straight with.

So the division of labour is exact:

| Artefact | Holds | Generated? |
|---|---|---|
| `honesty/card.html` | every number, version, region and census | yes — from the lock and the attestation |
| this file | every **sentence**, and the reasoning behind it | no — it is argued, not counted |
| `honesty/fixtures/` | stand-ins used before the corpus is frozen | committed, and loudly labelled |

A card built from those fixtures prints a full-width **NOT FOR CAMERA** banner, driven by the
`_fixture` marker **inside the data** rather than by a command-line flag — so a rehearsal build
cannot be smuggled onto camera by leaving an argument off. The generator also refuses to emit
any run of seven or more hexadecimal characters, because a commit id is a `sha256` over the JCS
envelope that nobody can choose in advance: a digest printed on this card would be a promise the
commit DAG has not made.

Where the attestation and this project's own disclosures both speak to a fact — the residency
split, the garbage-collection window — **the attestation wins**, and the card's provenance table
names which source supplied each value. A measurement always outranks a statement about a
measurement.

**The watermark is on screen for the whole film:**
`SYNTHETIC CORPUS · KESTREL RESOURCES IS FICTIONAL`

## 1 · REAL

Everything in this column happened, live, in front of the camera.

- **The database is CockroachDB Cloud.** Product, edition, version, cluster version, tier and
  region are printed on the card, read from the attestation. They are measurements, not
  documentation.
- **Every SQL result on screen executed live**, against that cluster, during the take. Each
  on-camera round trip — statement, SQLSTATE, constraint name, row count, timing — is written to
  `evidence/demo-run-<ts>/roundtrips.jsonl` and hashed, so the video is corroborated by an
  artefact rather than merely asserted.
- **The refusal is a database constraint, not application code.** The exhibit is a name:
  `gate_closed_when_issued`, a plain-column `CHECK` over a trigger-projected counter, evaluated
  inside a `SERIALIZABLE` transaction for every writer. The bypass beat proves the "every
  writer" half by running the same statement as **cluster admin over raw SQL**, with our
  application out of the path entirely.
- **The append-only refusal is also real.** Deleting the obligation raises from
  `mainline.fn_refuse_mutation` with its own message.
- **The `DROP CONSTRAINT` succeeds.** That is filmed deliberately. A cluster admin *can* remove
  the gate; what they cannot do is remove it unobserved, because the custodian patrol writes an
  attested leaf into the custody ledger naming the change. **The claim is tamper-evidence, and
  it is never tamper-proofing.** Anyone telling you a database can stop its own administrator is
  selling something.
- **The clearance-lattice refusal is a foreign key.** The worst available signature is not
  refused by a rule; there is no row for it to reference, so it is not representable.
- **The MCP session is CockroachDB's own public managed endpoint.** None of our code is between
  the prompt and the row.
- **The `EXPLAIN` output is unedited**, including the `vector search` node and its non-empty
  `prefix spans:` line. The index is named explicitly in the query, because the optimizer does
  not choose it at demo corpus scale — that is a measured fact recorded in the attestation, and
  pinning the index is the more deterministic engineering anyway.

**Where it runs, precisely.** The database is in Singapore; Bedrock inference is in Sydney.
Sydney is Advanced-tier only for CockroachDB Cloud, so it is absent from the Basic region list.
**Any claim of end-to-end Australian data residency is false for this deployment**, and the
card states the split rather than rounding it off.

## 2 · SYNTHETIC

Everything in this column was generated by us and corresponds to nobody.

- **The operator is fictional.** *Kestrel Resources Pty Ltd* and its four sites were cleared
  against the ASIC company register, ABN Lookup and IP Australia trade marks, with the query
  strings, dates and verbatim results recorded in `demo/operator/CLEARANCE.md`, plus three
  pre-cleared fallback names. That is the no-third-party-trademark rule satisfied
  affirmatively, rather than by hope.
- **The people are fictional.** Names, ranks, competencies and separations are generated. No
  real person appears, is depicted, or is characterised.
- **The incidents are fictional.** No real fatality or injury appears anywhere in the demo
  tenant. **No MSHA or CSB narrative ever enters it** — real corpora are used only in the
  offline evaluation harness, never here.
- **The documents are generated.** Seed, generator version, per-stream seeds, model
  identifiers, prompt versions, embedding provenance and the **renderer census** are all in
  `corpus.lock.json` and printed on the card. The census is *counted by the generator*, so the
  card cannot overstate or understate how much of the prose a model wrote — including the case
  where the answer is none of it.
- **The embeddings are fixture embeddings**, produced by a static CPU encoder and lifted to the
  production vector width by a fixed orthonormal matrix that preserves cosine similarity. The
  encoder id, the target dimension and the dtype on disk are printed on the card; the lift digest
  and the measured lexical-versus-semantic margin are in `corpus.lock.json`, where a reader can
  check them without a digest being flashed on screen for eight seconds. This changes which
  vectors are in the index; it does not change the `EXPLAIN` claim, which is about the index and
  the plan.

**The honest limit on the synthetic gold set.** It was authored by the same hand that authored
the causal structure, so it bounds our linker **from above** and it does not measure real-world
precision. The decoys and negative controls are written adversarially against it — same asset,
same window, same vocabulary, different hazard energy, different failed control — and the
real-corpus evaluation is the thing that settles the question. We say that here rather than
letting a strong synthetic number stand in for a real one.

## 3 · STAGED

Real components, arranged for a three-minute film. Nothing here is faked; things here are
*pre-positioned*, and this is the list.

- **Permit `WO-88213` is pre-seeded**, so the take begins at the moment the supervisor clicks
  merge instead of at the moment somebody opens a permit. The gate evaluation is live; the
  permit's existence is not news.
- **The judge-path exposure receipt is seeded with a long expiry — `2027-01-01` — and that is a
  demonstration convenience rather than the product's default.** `demo_permit.sql` says so in its
  own comment: the window was chosen so the admission beat keeps working for every judge for the
  whole judging period, rather than for a couple of hours after somebody ran the deploy. In the
  product a receipt's TTL is hours; the schema constrains only that a receipt expire after it was
  issued, and the application picks the window. **The mechanism is not staged.** The disposition
  still takes a composite foreign key onto the exact rows the same serializable transaction
  returned — §5 below — so a long expiry keeps the admission beat *available* and does nothing
  whatever to make it *pass*.
- **The film's own database uses a different receipt, and that one expires two hours after it is
  issued.** `scripts/proof/gate_refusal.py::seed_history` issues it; `seed_demo_state.py`, which
  calls that function, prints the resulting deadline on every run, in both modes. It prints it
  because with no live receipt the admission beat is **skipped** and the run reports
  `NOT PROVEN` — a gate that only ever refuses. Every refusal on camera still refuses, so this is
  the take nobody notices until the edit, which is exactly why the deadline is printed.
- **Two receipts, two expiries, two databases, on purpose.** The proof world and the demo world
  cannot share a database — that was measured rather than assumed, and it is recorded in
  `docs/submission/VIDEO-KIT.md` §B.9. The same split is why the two worlds name their permits
  differently: `WO-88213` is the console and corpus world's, the one the bullet above is about;
  `DEMO-PTW-0001` in `demo_permit.sql` is the demo-api world's. Neither expiry is changed to make
  this page tidier: the seeds are authoritative for their own database and this page is checked
  against them, never the other way round.
- **The ingestion of the 2013 report ran earlier** and is shown as a sped-up inset. It is a real
  run, replayed; it is not re-executed during the take.
- **Commit dates are corpus data, not time travel.** Every date on screen is a column value in
  the commit DAG. **`AS OF SYSTEM TIME` is never used to produce any frame of this film.** The
  measured GC window on this cluster is on the card, in minutes, and it is far short of the
  twenty-two years the beat-1 ancestry covers. Long-horizon versioning is the
  application-level commit DAG, and a query past that window is refused rather than silently
  wrong — which we keep as a conformance case rather than as a footnote.
- **The deliberation timer shows a corpus value.** `deliberation 00:47 · measured, never
  thresholded` is a recorded number from a seeded disposition. It is displayed because measuring
  it and refusing to threshold it is a deliberate position, not because forty-seven seconds
  means anything about anyone.
- **The custodian patrol's fifteen-second latency is its configured cadence**, not a
  best-case figure chosen after the fact.
- **The signing path may degrade.** If browser-bound WebAuthn does not hold on the day, signing
  falls back to OIDC plus a signed envelope, and the card says so **on the day** rather than
  quietly keeping the stronger sentence.
- **Cuts and pacing are edited.** Two punch-ins, no auto-zoom, no music at all, captions burned
  in by forced alignment against the known script rather than open transcription — which
  mangles exactly the tokens that carry the claim.

## 4 · NOT BUILT YET

The column that buys the other three their credibility. Judges have already watched forty demos
that overclaimed.

- **M14 SHEPARD — the Shepard lattice — is NOT BUILT.** It is the mechanical citator for
  engineering controls: treatment flags as a write precondition on an operational state
  transition. It is **specified only**, it is K7 work, and **it has no tables in the shipped
  schema.** An earlier draft of this script filmed it. That was caught in adversarial review
  and corrected, and the correction is why the diachronic beat films **M8, the defeater lease**,
  which is in the schema today and fires the identical revoke → re-open → epoch-pin →
  suspend-and-fork path. The extension point is written down in the repository rather than left
  for a reader to grep for.
- **M13 THE RATIO ENVELOPE, M15 CONSANGUINITY, M16 THE SECOND CLOCK, M17 THE TRANSPORT WARRANT,
  M18 BARRIER ESCROW, M19 DERATE, M21 THE WEAKENING TRIANGLE** — specified, each with a named
  extension point, none enforced by the database today.
- **M10 THE STANDING ASSAY ships inert.** The tables exist; the gate weight is one; the peer
  channel is off.
- **Adverse witnesses are not running.** Until one is, the ledger is tamper-evident to a holder
  of a checkpoint, and split-view resistance is not something we claim.
- **RFC 3161 timestamping and the drand beacon are deferred.** KMS-signed checkpoints into
  object storage under a compliance-mode lock ship instead.
- **Full recall calibration is deferred.** The panel is defined and runs nightly; conformal
  threshold selection and customer-grade floors are later work.
- **One environment, one throwaway verify cluster.** Multi-environment, fault-injection game
  days and automated disaster-recovery drills are later work.
- **Not provisioned:** customer-managed encryption keys and PrivateLink. Both are tier features
  this deployment does not have, and neither is claimed anywhere.
- **We never run live OT connectivity, and we never auto-remediate anything.** Ingestion is a
  periodic one-way export from the OT DMZ. The system detects and refuses; it does not act on
  plant.
- **We do not identity-proof anyone.** A signature binds to an enrolled credential; who that
  credential belongs to is the customer's identity provider's assertion, not ours.
- **Any per-person measurement is gated behind a customer-signed notified policy**, lives in a
  schema no MCP service account ever receives, and writes a read-of-a-profile record every time
  it is queried.

## 5 · The limit no schema retires

> **Nothing here separates a considered disposition from a rubber stamp.**

We are not going to pretend otherwise, and we are not going to bury it in a FAQ. What the
system does instead is narrower and true:

1. it makes the **question unavoidable** — a disposition takes a composite foreign key onto the
   exact rows the same serializable transaction returned, so *"it never showed me"* and *"I
   signed without looking"* cannot both be said;
2. it makes the **record precise** — frozen competency, a per-check defeater vocabulary, the
   evidence digest, and deliberation measured from a server-written timestamp on a row the
   kernel wrote rather than from anything a client supplied;
3. it makes the **worst stamp non-representable** — the clearance lattice has no row for the
   cell that would license it, so the foreign key refuses;
4. it makes the **second-worst self-revoking** — a `mechanism_absent` disposition is a lease
   with a compiled predicate, a bounded window and a stated probability, and when the site's own
   register falsifies it the lease is called automatically and the gate re-opens;
5. it makes the whole surface **measured and disclosed** rather than hidden — including every
   precursor the system declined to surface, with its arithmetic.

None of that reads sincerity. Naming a limit you cannot engineer away is not a weakness in the
pitch; it is the reason the rest of the pitch is believable.

## 6 · What else this film does not prove

- Not that the narrative in an ingested document is **true**. Content authenticity is out of
  scope; provenance — who submitted it, when, its digest, its locked object version — is in
  scope.
- Not that the retrieval was exhaustive over the **corpus**. It is exhaustive over **the
  retrieval that ran**, and the difference is the entire honesty of the mechanism.
- An approximate-nearest-neighbour result is not bit-identically replayable. What is claimed is
  replayability of the arithmetic and of the disclosed boundary.
- Not that a machine-written operations finding is **true**. An LLM report is evidence that a
  review occurred, never evidence of a condition — which is why every finding carries the SQL it
  ran and the digest of its result rows, so it can be re-run.
- Row-level security is a defence against a compromised application role. It is not a defence
  against a cluster administrator, and the bypass beat exists precisely to show what *is*.

## 7 · How to check that this document is not lying

```bash
python verticals/mainline/demo/honesty/gen_card.py --check     # card matches its inputs
python scripts/demo/claim_hygiene.py                           # no forbidden claim, anywhere
python scripts/demo/claim_hygiene.py --self-test               # and the checker can go red
```

The third command is the one that matters. A hygiene check that has never fired asserts nothing
about a repository whose whole pitch is that it refuses to overclaim.
