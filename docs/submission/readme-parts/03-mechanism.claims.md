## 1 · One claim is not carried forward, because the committed artefact refutes it

The brief instructed me to write that *refusal is structurally redundant, proven by an
unwelding harness that disables the trigger or drops the constraint one at a time and the
write still fails.* **That sentence is false against this repository's own measurement**, and
the no-overclaim rule outranks the content list.

`packages/trappoint-conformance/REFUSAL_DEPTH.md` — generated by `unweld/test_unweld.py`,
27 histories, `CockroachDB CCL v26.2.5` — records in its own words: *"9 of 9 gated merge-gate
histories measured at depth 1, and 15 mechanism(s) opened a gate when removed alone. The
architecture's sentence … does not hold for those histories as the schema currently stands."*
`CF-01`, `CF-02`, `CF-03`, `CF-04`, `CF-05`, `CF-06`, `CF-31`, `CF-45` and `CF-70` are each
listed at depth 1 under the heading *Histories below the floor on this run*.

The fragment therefore states the opposite of the old README sentence, gives the harness's
own reason (`fn_permit_merge_gate` declines to raise while the projection agrees, so the
named `CHECK` stays the exhibit rather than being pre-empted by an unnamed `P0001`), and
quotes the file's pre-committed response to a depth of one: *cut the mechanism, do not ship
it.* **Verify:** `grep -c "depth 1" packages/trappoint-conformance/REFUSAL_DEPTH.md` → 9.

Two secondary consequences, both recorded rather than smoothed:

* `REFUSAL_DEPTH.md` was measured on the `trappoint-ref` reference profile with **six
  stand-in relations** supplied so the tree would apply, and it says so in its own Provenance
  note. The fragment says "measured", names the file, and claims nothing about the mainline
  tree that the file does not.
* The old README's *"delete the `RAISE` and the write still fails twice over"* framing has no
  surviving home in `README.md`. It is `DROPPED`, and §1 above is the reason.
