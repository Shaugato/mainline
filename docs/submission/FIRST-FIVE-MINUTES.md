# The judge's first five minutes

**Not a claim. A recording.** Every row below came out of a program that cloned this
repository at `HEAD` into a temporary directory and ran, inside that clone, the exact
commands `README.md` and `docs/release/QUICKSTART.md` tell a stranger to run. The exit
codes, the durations and the output excerpts are what the subprocesses actually printed.

```
python scripts/submission/judge_dry_run.py \
    --dsn "postgresql://root@127.0.0.1:26257/defaultdb?sslmode=disable" \
    --probe-threshold
```

The machine-readable record is [`qa/judge-dry-run.json`](../../qa/judge-dry-run.json)
(schema `mainline.qa.judge-dry-run/1`). This page is that file in prose. Where the two
disagree, **the JSON is right and this page is stale** — it is generated by hand, the
JSON is not.

A step that did not run says `NOT RUN`. It never says `PASS`.

**The machine.** Windows 11 (`10.0.26200`), `git 2.50.0.windows.1`, Docker 29.3.1,
`HKLM\…\FileSystem\LongPathsEnabled = 0` (the Windows default). On `PATH`: `git`,
`docker`, `python`, `node`. **Not** on `PATH`: `just`, `uv`. Database: the pinned
`cockroachdb/cockroach:v26.2.5` container `mainline-crdb`, already running, and shared
with the rest of the build fleet while this ran — so **every duration is an upper bound,
not a benchmark**. Source: `HEAD` = `bb21962`, branch `master`.

---

## 0 · The result in five lines

1. On Windows, **a plain `git clone` fails outright** if the destination path is longer
   than **44 characters**. Measured, not calculated: 44 works, 45 does not.
2. `git clone -c core.longpaths=true` fixes the clone, and **does not fix the tree** —
   two fixture files then exist that no ordinary program on the machine can open.
3. Inside a good clone the **central claim reproduces**: `VERDICT PROVEN`, in **70.4
   seconds**, against the pinned local node — with the caveat the proof prints itself,
   `246/261 applied, 15 failed`.
4. `just` and `uv` are **not installed on the machine this was measured on**, so three of
   the four documented commands were run through their fallbacks and the fourth,
   `just setup`, could not be run at all. `python scripts/qa/doctor.py` says exactly that,
   in a table, and exits 1. That is the doctor working, not the clone failing.
5. A judge who skips `just setup` gets a repository whose proof **cannot run at all** —
   and the dry run records exactly that, by running everything twice: once with a bare
   interpreter and once with the workspace installed.

## 1 · Minute one — the clone

### The arithmetic

Windows' `MAX_PATH` is 260 characters *including* the terminating NUL, so 259 are usable
by any program that has not opted in to long paths. A checkout costs

```
len(clone destination) + 1 (separator) + len(path relative to the repo root)
```

The longest tracked path in this repository is **214 characters**:

```
verticals/mainline/apps/console/fixtures/bundles/blk-07/frames/GET~20~2Fv1~2Fclauses~2F018f3a30-…~2Fancestry~3Fas_of~3D5f91…e576.json
```

`259 − 1 − 214 = 44`. So the arithmetic predicts a destination of at most 44 characters.
`python scripts/submission/check_path_lengths.py` prints that number and enforces it as a
falling-only budget.

### The measurement

The arithmetic is a prediction. `--probe-threshold` performs **real clones** into
destinations of increasing length under a short probe root and binary-searches the
boundary, twice — once as the README documents it, once with the flag.

| variant | search range | largest destination that works | first destination that fails | tree still readable up to | first unreadable tree | clones taken |
|---|---|---|---|---|---|---|
| `git clone` (as documented) | 9 – 140 chars | **44** | **45** | 44 | 45 | 9 |
| `git clone -c core.longpaths=true` | 9 – 140 chars | no failure up to **140** | — | **44** | **45** | 9 |

Two thresholds, and the second is the one that is easy to miss. With the flag, git
creates the file; with `LongPathsEnabled` set to `0` in the registry — the Windows
default, and the value on the machine measured here — **CPython raises `FileNotFoundError`
on the same file**. The clone flag buys a complete `.git`, a clean `git status`, and two
fixtures the console loader cannot read.

The failure a judge sees without the flag:

```
error: unable to create file verticals/mainline/apps/console/fixtures/bundles/blk-07/frames/
        GET~20~2Fv1~2Fclauses~2F…~2Fancestry~3Fas_of~3D5f91…e576.json: Filename too long
fatal: unable to checkout working tree
warning: Clone succeeded, but checkout failed.
```

`git clone` exits **128** and leaves a tree that looks almost complete. Nothing tells the
judge which files are missing.

### The three clones this dry run actually performed

| # | what was typed | destination | result | exit | `Filename too long` | seconds |
|---|---|---|---|---|---|---|
| 1 | `git clone <url> <dest>` into the system temp directory | 66 chars | **FAIL** | 128 | 2 | 7.4 |
| 2 | `git clone -c core.longpaths=true <url> <dest>`, same place | 66 chars | **PASS (CAVEATED)** | 0 | 0 | 7.8 |
| 3 | `git clone <url> <dest>` into a destination inside the safe prefix | 11 chars | **PASS** | 0 | 0 | 4.1 |

Clone 2's caveat, recorded verbatim in the JSON: the longest file lands at **281**
characters, `git status` is clean, and `open()` on that file raises `FileNotFoundError:
errno 2`. Clone 3 is the one the steps below ran in — longest file at **226** characters,
zero dirty lines, readable — and it is the only one of the three that a judge could work
in without knowing anything about `MAX_PATH`.

### What a judge should be told to type

```bash
git clone -c core.longpaths=true https://github.com/Shaugato/mainline.git
cd mainline
```

On macOS and Linux the flag is a no-op. On Windows it is the difference between a working
tree and a silent one.

### Why the files are not simply renamed

The frame names are **derived from the request**, not chosen —
`verticals/mainline/apps/console/src/data/resources.ts:373` returns
``frames/${out}.json`` — so a rename breaks the console's replay loader and the bundle
manifest at the same time. Lead ruling **L-2**: the judge-facing repair is the clone flag;
the engineering repair is a truncate-and-hash in the encoder, and that file belongs to the
UI domain, not to this one.

The exposure is therefore **counted rather than hidden**. `qa/judge-dry-run.json →
path_lengths.budget` holds two numbers, both measured today, both falling-only:

```
max_tracked_path_chars              214    (of 7,120 tracked files)
files_unclonable_at_typical_prefix    2    (a 60-character destination)
policy                     falling-only
budget_status                        OK
```

```
python scripts/submission/check_path_lengths.py            # measure and enforce
python scripts/submission/check_path_lengths.py --update   # lower a number that fell
python scripts/submission/check_path_lengths.py --self-test
```

A number that falls may be lowered with `--update`. A number that rises names the paths
that raised it and exits **1** — `--update` will not cover up a rise. The longest single
name component is 151 characters, 104 short of NTFS's 255-character limit, so the pressure
is entirely on the total, not on any one filename.

## 2 · Minutes two to five — the commands

### What the front door promises

`README.md` and `docs/release/QUICKSTART.md` both open with the same four commands. On the
machine this was measured on, **`just` is not on `PATH` and neither is `uv`**, so none of
the four is runnable as written. The right-hand column is what was executed instead.

| documented | in README | in QUICKSTART | runnable here | what was run instead |
|---|---|---|---|---|
| `just doctor` | yes | yes | **no — `just` not on PATH** | `python scripts/qa/doctor.py` |
| `just setup` | yes | yes | **no — `just` not on PATH** | *(not run; `uv` is absent too — see §4)* |
| `just up` | yes | yes | **no — `just` not on PATH** | `docker compose -f compose.yaml config` |
| `just prove` | yes | yes | **no — `just` not on PATH** | `python scripts/proof/gate_refusal.py --dsn …` |

This is a **finding about the host**, not about the clone. The README already says
`python scripts/qa/doctor.py` needs nothing but the interpreter, and that is the path a
judge without `just` will take.

The dry run executes the whole sequence **twice**, with two different interpreters, because
the difference between them *is* the answer to "what happens if a judge skips step 2".

### Run A — a bare interpreter, the state before `just setup`

`python` on `PATH`: CPython **3.14.3** at `C:\Python314\python.EXE`. `psycopg` and
`pytest` happen to be installed globally on this machine; **`trappoint_migrate` is not**,
because the workspace has never been installed into this interpreter.

| what a judge types | status | exit | seconds | what it printed |
|---|---|---|---|---|
| `python scripts/qa/doctor.py` | **FAIL** *(expected)* | 1 | 3.1 | `FAIL uv (python workspace) not on PATH` · `FAIL just (command surface) not on PATH` · `NOT READY - 2 blocking checks` |
| `docker compose -f compose.yaml config` | **PASS** | 0 | 0.5 | `image: cockroachdb/cockroach:v26.2.5` |
| `python scripts/proof/gate_refusal.py --dsn …` | **FAIL** *(expected)* | 1 | 0.9 | `ModuleNotFoundError: No module named 'trappoint_migrate'` |
| `python -m pytest --crdb=none --collect-only -q` | **FAIL** *(expected)* | 4 | 0.7 | `ERROR: pyproject.toml: 'minversion' requires pytest-9.1, actual pytest-9.0.3` |
| `python scripts/qa/check_reuse.py` | **NOT PRESENT** | — | — | the file is not in the clone |

*Expected* here means the JSON carries `expected_failure: true` and a
`nonzero_expected_because` sentence naming the missing precondition. The status still says
`FAIL`, because that is what happened.

Two things are worth pulling out of that table. The proof dies on an **import**, not on the
database — so a judge who has a cluster but no workspace still gets nothing. And `pytest`
never reaches collection at all: `pyproject.toml` sets `minversion` to **9.1** and the
globally installed pytest is **9.0.3**, so the run ends before a single test is found.

### Run B — the workspace venv, the state after `just setup`

CPython **3.13.14** at `<repo>/.venv/Scripts/python.exe`.

| what a judge types | status | exit | seconds | what it printed |
|---|---|---|---|---|
| `python scripts/qa/doctor.py` | **FAIL** *(expected)* | 1 | 2.8 | `FAIL uv` · `FAIL just` · `NOT READY - 2 blocking checks` · 1 advisory (`gc.ttlseconds` 14400 vs 4500) |
| `docker compose -f compose.yaml config` | **PASS** | 0 | 0.5 | `image: cockroachdb/cockroach:v26.2.5` |
| `python scripts/proof/gate_refusal.py --dsn …` | **PASS** | 0 | **70.4** | `chain 246/261 applied, 15 failed, 51.0s` · `VERDICT PROVEN` |
| `python -m pytest --crdb=none --collect-only -q` | **PASS** | 0 | 30.1 | `8849 tests collected in 28.24s` |
| `python scripts/qa/check_reuse.py` | **NOT PRESENT** | — | — | the file is not in the clone |

**The whole sequence, from a clean clone to `VERDICT PROVEN`, is under two minutes.** Not
five. The five minutes are spent on the clone flag nobody told the judge about, and on
`just setup`, which this machine cannot run.

## 3 · What the proof printed, inside the clone

```
chain         246/261 applied, 15 failed, 51.0s
REFUSAL       REFUSED [23514] gate_closed_when_issued (reported)
DRIFT         REFUSED [P0001] mainline.fn_permit_merge_gate (parsed)
ADMISSION     ADMITTED [00000]
VERDICT       PROVEN
```

Three beats, and all three are load-bearing. The first refusal is a plain `CHECK`. The
second is the gate under attack: the projected counter is forced to zero out of band and
the merge is refused **anyway**, because `mainline.fn_permit_merge_gate` re-derives the
obligation count instead of trusting the column. The third is the same history *admitted*
after one signed disposition — because a gate that always refuses is a broken gate, not a
safe one.

**The caveat is in the first line and is not negotiable.** `246/261 applied, 15 failed`.
Five tables in the schema have consumers and no producer migration; the fifteen consumer
migrations that depend on them fail, by name and SQLSTATE, in the evidence JSON the proof
writes. The verdict is `PROVEN`; the chain is not clean; the proof says both.

This is therefore recorded in `qa/judge-dry-run.json` as
`verdict: "PROVEN_WITH_CAVEATS"` — `PROVEN` is reserved for a run whose chain reports
`0 failed`.

## 4 · The gaps, in the order they will hurt

1. **The remote is behind this disk.** `HEAD` is 2 commits ahead of `origin/master` and
   **98 tracked files differ**. Everything on this page was measured against a clone of
   the *local* repository. A judge clones the remote — whose `README.md` does not contain
   the four commands at all. Until `git push` runs, this page describes a repository the
   public cannot see. This is the single highest-value action in the submission.
2. **59 files on the author's disk are in neither.** Modified or untracked, therefore
   invisible to any clone. Among them are the migrations that would take the chain from
   246/261 towards a clean run.
3. **`scripts/qa/check_reuse.py` is `NOT PRESENT` in the clone.** `.github/workflows/ci.yml`
   names that exact path in its `checkers` job and every substantive job declares
   `needs: [checkers]`, so the Actions tab of the public repository is red at job zero.
   It is the only step in this dry run whose failure is *unexpected*, and it is the only
   reason `judge_dry_run.py` exits non-zero. Re-run the dry run once that file lands.
4. **The globally installed `pytest` is too old for `pyproject.toml`.** `minversion` is
   `9.1`; the machine's global pytest is `9.0.3`, so on a bare interpreter the suite errors
   out (exit 4) before collecting anything. Inside the workspace venv the same command
   collects **8,849 tests** and exits 0. The remedy is `just setup`, which is the point —
   but the error message a judge sees names a version, not a missing step.
5. **`just` and `uv` are not installed here**, so `just setup` has never been executed on
   this machine and cannot be reported on. The four documented commands were all run
   through fallbacks.
6. **The clone flag does not make the tree readable.** Two fixtures are unreachable by any
   non-long-path-aware program at any destination over 44 characters. `pytest` and the
   proof do not touch them; the console's replay loader does.
7. **The dry run's interpreters import workspace code from outside the clone.** The venv is
   an editable install pointing at `D:\CoackroachDBxAWS\mainline\packages\…`, so the *SQL*,
   the *migrations* and the *scripts* under test are the clone's, but the installed Python
   packages are the host's. The JSON records every module whose origin is outside the
   clone, by path, under `runs[].interpreter.modules_resolved_outside_the_clone`. A clean
   room measurement needs `uv sync` inside the clone, and `uv` is not installed here.

## 5 · What this run did **not** test

Naming these is the point of the instrument.

* **`just setup` / `uv sync --all-packages`** — never executed; `uv` is absent.
* **`just up`** — the compose file was parsed (`docker compose config`, exit 0), not
  started. The node used was the already-running pinned container `mainline-crdb`.
* **The conformance suite** (`just conform`) — out of scope for the four commands, and
  `docs/HONESTY.md` already records that it has never been demonstrated.
* **The TypeScript console** — 278 files, zero CI coverage, and its fixtures are the very
  files that break the Windows clone.
* **Anything against the remote.** Everything here is a clone of the local repository.
* **Any cloud service.** No AWS call, no CockroachDB Cloud call, no network beyond the
  local clone and a local DSN.

Durations were recorded on the founder's Windows 11 workstation **while other build
workers were running their own jobs against the same single-node container**. They are
upper bounds, not benchmarks.

## 6 · The JSON, for whoever renders from it

`qa/judge-dry-run.json`, schema `mainline.qa.judge-dry-run/1`. Stable top-level keys:

| key | what it holds |
|---|---|
| `host` | platform, interpreter, git and docker versions, `tools_on_path`, `windows_longpaths_enabled` |
| `source` | the repository cloned: `head`, `branch`, `remote`, `commits_ahead_of_origin`, `files_differing_from_origin_master`, `origin_master_readme_has_the_documented_commands`, `working_tree_modified_or_untracked` |
| `operator_notes` | free text passed with `--note`, recorded verbatim |
| `path_lengths` | the measurement from `check_path_lengths.py`, including `budget` (falling-only) and `budget_status` |
| `clone_threshold` | `without_longpaths` and `with_longpaths`, each with `max_working_dest_chars`, `first_failing_dest_chars`, `max_readable_dest_chars`, `min_unreadable_dest_chars`, and every `probes[]` entry |
| `clone_attempts` | each clone tried, with `label`, `dest_chars`, `longpaths`, `classification`, `health` |
| `clone_used` | which clone the steps ran in |
| `runs[]` | `{interpreter, steps[]}` — one per interpreter |
| `runs[].steps[]` | `id`, `documented_as`, `typed`, `argv`, `status`, `exit_code`, `duration_s`, `output.{lines_total,head,tail,elided}`, and for the proof `chain_line`, `refusal_lines`, `verdict_line` |
| `findings[]` | `{severity, headline, detail}` |
| `verdict` | `PROVEN` / `PROVEN_WITH_CAVEATS` / `NOT_PROVEN` / `NOT_RUN` |
| `reproduce` | the command that regenerates the file |

Status vocabulary, also written into the file under `status_vocabulary`:

`PASS` · `PASS (CAVEATED)` · `FAIL` · `TIMEOUT` · `SKIPPED` · `NOT RUN` · `NOT PRESENT`.

A step whose non-zero exit is the *correct* answer — `doctor.py` on a machine with no
`uv` and no `just` — still says **`FAIL`**, because that is what happened. It carries
`expected_failure: true` and a `nonzero_expected_because` sentence, and it is exempt from
the program's own exit code. Renaming it `PASS` would be the one move this repository
exists to refuse.

## 7 · Reproduce every number on this page

```bash
# the whole dry run, including the real-clone threshold search (slow: ~20 clones)
python scripts/submission/judge_dry_run.py \
    --dsn "postgresql://root@127.0.0.1:26257/defaultdb?sslmode=disable" \
    --probe-threshold

# the same thing with no database at all; the proof is recorded as a named SKIP
python scripts/submission/judge_dry_run.py --skip-cluster

# the path-length budget on its own, and its built-in checks
python scripts/submission/check_path_lengths.py
python scripts/submission/check_path_lengths.py --self-test
```

`judge_dry_run.py` exits `0` when every step that was expected to pass did, `1` when
something did not (the JSON is still written — publish it), and `2` when the dry run could
not start at all.
