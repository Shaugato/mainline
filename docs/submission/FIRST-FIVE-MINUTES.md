# The judge's first five minutes

## Sixty seconds first — what these five minutes are five minutes *of*

**A crew is about to open a machine and work inside it, and somebody has to approve the job
before it starts.** In most organisations that approval is a signature on a form, and the form
knows nothing about the past.

**In March 2019 a worker was hurt doing this same kind of work.** The machine was declared
locked off without anyone confirming it was actually at zero pressure, and residual hydraulic
pressure released while a guard was being removed. The investigation named the written rule
meant to prevent exactly that: *"Before any intrusive work, stored energy shall be isolated,
locked and verified at zero by a competent person."*

**Seven years later a new job relies on that same rule, and nobody has answered for the 2019
failure on this particular job. The approver records the approval — and the database refuses
to store it.** Not a warning banner, not a policy service that another code path can go
around: the storage engine itself declines the write, and returns the one unanswered item that
caused it. Set the counter it checks down to zero by hand, and it refuses a second time,
because it recounts the underlying rows instead of believing the counter. Sign a proper answer
to the 2019 debt and it admits the very same job — a gate that always refuses would be broken
rather than safe.

**The story is invented, and the data says so about itself.** The incident row is titled
`SYNTHETIC — Stored energy release during intrusive work` and its own narrative field reads
*"No real incident, no real site, no real fatality: this narrative was written for the MAINLINE
demonstration and describes nobody"*
(`verticals/mainline/db/seeds/demo/demo_world.sql:275`). **The three refusals are not
invented**, and once the setup steps in §2 are taken, one command reproduces all three on your
own hardware, against a database you started yourself.

**What to click.** Nothing on this page needs an account, a key, or any credential of ours.
§2 is the four commands and §3 is what the last one printed. **This page is the unflattering
version**: it is a recording of a program that cloned this repository into a temporary
directory and ran those commands, including every way they went wrong — a clone that failed on
a path length, a proof that died on a missing import, a `pytest` too old to start collecting.
If you want the short path instead, [`JUDGE-START.md`](JUDGE-START.md) is ninety seconds, then
five minutes, then an optional credentialled step — and its opening block names the five parts
of this project that are hardest to find anywhere else.

## 1 · Minute one — the clone

### The arithmetic

Windows' `MAX_PATH` is 260 characters *including* the terminating NUL, so 259 are usable
by any program that has not opted in to long paths. A checkout costs

```
len(clone destination) + 1 (separator) + len(path relative to the repo root)
```

The longest tracked path in this repository is **214 characters**:

```
verticals/mainline/apps/console/fixtures/bundles/blk-07/frames/GET~20~2Fv1~2Fclauses~2F018f3a30-…~2Fancestry~3Fas_of~3D5f91…e576.json
```

`259 − 1 − 214 = 44`. So the arithmetic predicts a destination of at most 44 characters.
`python scripts/submission/check_path_lengths.py` prints that number and enforces it as a
falling-only budget.

### The measurement

The arithmetic is a prediction. `--probe-threshold` performs **real clones** into
destinations of increasing length under a short probe root and binary-searches the
boundary, twice — once as the README documents it, once with the flag.

| variant | search range | largest destination that works | first destination that fails | tree still readable up to | first unreadable tree | clones taken |
|---|---|---|---|---|---|---|
| `git clone` (as documented) | 9 – 140 chars | **44** | **45** | 44 | 45 | 9 |
| `git clone -c core.longpaths=true` | 9 – 140 chars | no failure up to **140** | — | **44** | **45** | 9 |

Two thresholds, and the second is the one that is easy to miss. With the flag, git
creates the file; with `LongPathsEnabled` set to `0` in the registry — the Windows
default, and the value on the machine measured here — **CPython raises `FileNotFoundError`
on the same file**. The clone flag buys a complete `.git`, a clean `git status`, and two
fixtures the console loader cannot read.

The failure a judge sees without the flag:

```
error: unable to create file verticals/mainline/apps/console/fixtures/bundles/blk-07/frames/
        GET~20~2Fv1~2Fclauses~2F…~2Fancestry~3Fas_of~3D5f91…e576.json: Filename too long
fatal: unable to checkout working tree
warning: Clone succeeded, but checkout failed.
```

`git clone` exits **128** and leaves a tree that looks almost complete. Nothing tells the
judge which files are missing.

### The three clones this dry run actually performed

| # | what was typed | destination | result | exit | `Filename too long` | seconds |
|---|---|---|---|---|---|---|
| 1 | `git clone <url> <dest>` into the system temp directory | 66 chars | **FAIL** | 128 | 2 | 7.4 |
| 2 | `git clone -c core.longpaths=true <url> <dest>`, same place | 66 chars | **PASS (CAVEATED)** | 0 | 0 | 7.8 |
| 3 | `git clone <url> <dest>` into a destination inside the safe prefix | 11 chars | **PASS** | 0 | 0 | 4.1 |

Clone 2's caveat, recorded verbatim in the JSON: the longest file lands at **281**
characters, `git status` is clean, and `open()` on that file raises `FileNotFoundError:
errno 2`. Clone 3 is the one the steps below ran in — longest file at **226** characters,
zero dirty lines, readable — and it is the only one of the three that a judge could work
in without knowing anything about `MAX_PATH`.

### What a judge should be told to type

```bash
git clone -c core.longpaths=true https://github.com/Shaugato/mainline.git
cd mainline
```

On macOS and Linux the flag is a no-op. On Windows it is the difference between a working
tree and a silent one.

### Why the files are not simply renamed

The frame names are **derived from the request**, not chosen —
`verticals/mainline/apps/console/src/data/resources.ts:373` returns
``frames/${out}.json`` — so a rename breaks the console's replay loader and the bundle
manifest at the same time. Lead ruling **L-2**: the judge-facing repair is the clone flag;
the engineering repair is a truncate-and-hash in the encoder, and that file belongs to the
UI domain, not to this one.

The exposure is therefore **counted rather than hidden**. `qa/judge-dry-run.json →
path_lengths.budget` holds two numbers, both falling-only:

```
max_tracked_path_chars              214    (of 7,120 tracked files)
files_unclonable_at_typical_prefix    2    (a 60-character destination)
policy                     falling-only
budget_status                        OK
```

> **RE-MEASURED 2026-08-14, and both numbers fell — which is the only direction this budget
> permits without a named exception.** `python scripts/submission/check_path_lengths.py`,

name component is 151 characters, 104 short of NTFS's 255-character limit, so the pressure
is entirely on the total, not on any one filename.

## 6 · The JSON, for whoever renders from it

`qa/judge-dry-run.json`, schema `mainline.qa.judge-dry-run/1`. Stable top-level keys:

| key | what it holds |
|---|---|
| `host` | platform, interpreter, git and docker versions, `tools_on_path`, `windows_longpaths_enabled` |
| `source` | the repository cloned: `head`, `branch`, `remote`, `commits_ahead_of_origin`, `files_differing_from_origin_master`, `origin_master_readme_has_the_documented_commands`, `working_tree_modified_or_untracked` |
| `operator_notes` | free text passed with `--note`, recorded verbatim |
| `path_lengths` | the measurement from `check_path_lengths.py`, including `budget` (falling-only) and `budget_status` |
| `clone_threshold` | `without_longpaths` and `with_longpaths`, each with `max_working_dest_chars`, `first_failing_dest_chars`, `max_readable_dest_chars`, `min_unreadable_dest_chars`, and every `probes[]` entry |
| `clone_attempts` | each clone tried, with `label`, `dest_chars`, `longpaths`, `classification`, `health` |
| `clone_used` | which clone the steps ran in |
| `runs[]` | `{interpreter, steps[]}` — one per interpreter |
| `runs[].steps[]` | `id`, `documented_as`, `typed`, `argv`, `status`, `exit_code`, `duration_s`, `output.{lines_total,head,tail,elided}`, and for the proof `chain_line`, `refusal_lines`, `verdict_line` |
| `findings[]` | `{severity, headline, detail}` |
| `verdict` | `PROVEN` / `PROVEN_WITH_CAVEATS` / `NOT_PROVEN` / `NOT_RUN` |
| `reproduce` | the command that regenerates the file |

Status vocabulary, also written into the file under `status_vocabulary`:

`PASS` · `PASS (CAVEATED)` · `FAIL` · `TIMEOUT` · `SKIPPED` · `NOT RUN` · `NOT PRESENT`.

A step whose non-zero exit is the *correct* answer — `doctor.py` on a machine with no
`uv` and no `just` — still says **`FAIL`**, because that is what happened. It carries
`expected_failure: true` and a `nonzero_expected_because` sentence, and it is exempt from
the program's own exit code. Renaming it `PASS` would be the one move this repository
exists to refuse.
