**Analyst:** `w1-demo-identity` · **Date:** 2026-08-13 · **Mode:** READ-ONLY

## Verdict

**36 definition pairs enumerated across 9 entity identifiers and 2 subject strings.
9 DIVERGENT, 20 LATENT, 7 HELD.** The slice is not clean, but it is also not on fire:
the single divergence that could reach a judge — the permit id — is neutralised at
runtime by `infra/modules/demo-api/main.tf:155` and by the now fail-closed
`transitions._demo_guard`, and I confirmed by execution that `site_id`, `clause_uuid`
and `event_id` are **inert**: a gate run driven with all three set to garbage still
returns `verdict: PROVEN` with four correct beats. `variables.tf:320-340`'s claim that
the site is projected away is TRUE and is now measured rather than argued —
`mainline.disposition.site_id` is overwritten by `0102_fn_disposition_project.sql:208`
from `blocking_check.site_id`, and the column carries **no constraint at all**, so the
projector is the only thing between the client's value and the stored row.

What is left is the census's own target: **almost nothing holds any of these pairs
together.** The deployed permit id exists as a literal in seven files and exactly one
pair of them (`seed_demo.py:104` ↔ `demo_permit.sql:90`) is checked by anything that
executes. The Terraform default is pinned only by an *inequality* assertion — I ran the
test's own regex and predicate against hypothetical values and a one-character typo
passes. Five of the seven identifiers `seed_demo.py` declares "so that a drift between
the SQL and the verifier is a test failure" are never queried at all; they are copied
straight into `evidence/deploy/cloud-seed.json` as unverified claims about the Cloud
database. And `docs/deploy/gate-run-contract.md:217-218` still tells a reader that the
uuid5 family *is* the seeded subject and that the seed and the API "cannot silently
disagree".
